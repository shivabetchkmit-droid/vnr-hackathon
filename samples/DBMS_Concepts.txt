# Database Management Systems (DBMS) - Core Concepts

## 1. Aggregation in DBMS
Aggregation is an abstraction through which relationships are treated as higher-level entities.
In SQL and relational query processing, aggregation operations compute summary statistics over collections of values:
- COUNT(): Returns the total number of tuples meeting the criteria.
- SUM(): Calculates the mathematical total of numeric values in an attribute.
- AVG(): Determines the arithmetic mean of a column.
- MIN() / MAX(): Retrieve the lowest and highest values respectively.

### GROUP BY and HAVING
The `GROUP BY` clause groups rows that have the same values in specified columns into summary rows.
The `HAVING` clause specifies conditions that filter which group results appear in the output, applied AFTER the aggregation occurs, whereas `WHERE` filters rows BEFORE aggregation.

Example:
```sql
SELECT department_id, AVG(salary) AS avg_sal, COUNT(employee_id) AS total_staff
FROM employees
WHERE status = 'Active'
GROUP BY department_id
HAVING AVG(salary) > 75000;
```

## 2. ACID Properties
Transaction processing guarantees reliability through four fundamental pillars:
1. Atomicity: "All or nothing" — if any part of the transaction fails, the entire transaction is rolled back.
2. Consistency: Any transaction will bring the database from one valid state to another, maintaining all schema constraints and foreign keys.
3. Isolation: Concurrent execution of transactions yields the same state that would be obtained if transactions were executed serially.
4. Durability: Once a transaction has been committed, it will remain committed even in the event of a power loss, crash, or system failure.

## 3. Database Normalization
Normalization organizes database tables to reduce redundancy and improve data integrity:
- 1NF (First Normal Form): Atomic values, each column contains unique values, no repeating groups.
- 2NF (Second Normal Form): In 1NF and all non-key attributes are fully functionally dependent on the entire primary key.
- 3NF (Third Normal Form): In 2NF and no transitive functional dependencies (non-prime attributes depend only on the primary key).
- BCNF (Boyce-Codd Normal Form): Strict 3NF where for every functional dependency X -> Y, X must be a super key.
